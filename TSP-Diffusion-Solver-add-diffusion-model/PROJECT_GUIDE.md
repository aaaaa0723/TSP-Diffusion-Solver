# TSP Diffusion Solver 專案詳解

這份文件從零解釋專案在解什麼問題、擴散模型如何訓練與產生結果，以及 decoder 怎麼把模型的輸出轉成一條可行路線。可以把它當作程式導覽、報告準備筆記和名詞表。

> **先記住整體分工：**模型負責估計「每一對城市應不應該相連」的分數；decoder 負責把分數整理成「每個城市剛好走一次、最後回到起點」的完整巡迴路線。擴散模型本身不會直接輸出城市順序。

## 1. 專題要解的問題

### 1.1 TSP 是什麼

旅行推銷員問題（Traveling Salesperson Problem, TSP）給定一群城市及城市間距離，要求找一條路線：

1. 從某個城市出發。
2. 每座城市恰好拜訪一次。
3. 最後回到出發城市。
4. 整段路線的總距離盡量短。

若城市座標為 `(x_i, y_i)`，城市 `i` 到 `j` 的歐氏距離是：

```text
d(i,j) = sqrt((x_i - x_j)^2 + (y_i - y_j)^2)
```

路線可寫成 `π = (π_0, π_1, …, π_{N-1}, π_0)`，其長度為：

```text
L(π) = Σ d(π_k, π_{k+1})，k = 0 到 N-1
```

TSP 的難處是城市數增加時，可能路線數量急速增加。模型因此不直接列舉所有城市排列，而是學習哪些城市連線比較可能出現在好路線中，再交由 decoder 組成完整巡迴。

### 1.2 本專案的資料

目前資料產生程式預設建立 1000 個隨機 TSP 案例，每個案例 494 座城市。每座城市有二維座標，座標均勻分布在面積約 2215 平方公里的正方形區域中，邊長約 `sqrt(2215) ≈ 47.07 km`。

資料主要欄位：

| 欄位 | 典型形狀 | 意義 |
|---|---:|---|
| `coords` | `[案例數, 城市數, 2]`，例如 `[1000, 494, 2]` | 每個案例的 `(x,y)` 座標，單位為 km |
| `adjacencies` | `[案例數, 城市數, 城市數]`，例如 `[1000, 494, 494]` | OR-Tools 參考路線的相鄰關係矩陣 |

`adjacencies[s,i,j] = 1` 表示參考路線從城市 `i` 走到 `j`。資料產生器用 OR-Tools 的 `PATH_CHEAPEST_ARC` 建立初始解，再用 `GUIDED_LOCAL_SEARCH` 改善，並設定每個案例的搜尋時間上限。這是一個實用的**啟發式參考解**，不能保證是數學上的全域最短解。

距離成本在 OR-Tools 中會將公里乘 1000 後取整數；儲存座標仍是浮點數公里，因此畫圖及重新計算路長時使用座標的歐氏距離。

### 1.3 為什麼標籤要變成無向矩陣

TSP 巡迴中，若路線包含 `i → j`，同一條幾何邊也可以視作 `j ↔ i`。訓練前會將方向矩陣對稱化：

```text
A = max(A, Aᵀ)
```

得到的 `A` 是 `[N,N]` 的二元鄰接矩陣。對角線代表城市連到自己，沒有意義，因此訓練 loss 會忽略對角線。對一條正常巡迴而言，每個城市在無向表示下應連到兩條邊，所以每列理想上有兩個 1。這個條件是標籤路線的性質；模型預測的矩陣不會自動滿足它。

## 2. 擴散模型的直覺

擴散模型可以想成兩個方向的程序：

- **正向加噪**：逐步破壞一份已知資料，讓它越來越像隨機雜訊。
- **反向去噪**：訓練神經網路從部分被破壞的資料中辨認原本的結構；推論時從隨機狀態開始，多次去噪，形成模型認為合理的結果。

影像擴散常見的狀態是像素或連續數值；本專案的狀態是「城市邊是否存在」的二元值。因此它是**離散／類別式邊擴散**：每個城市對的狀態是 0（不相連）或 1（相連）。

擴散的目標不是一步猜出一整串城市順序，而是在每一輪從一張雜亂的邊矩陣中推估乾淨的巡迴邊矩陣。推論最後保留的是每條邊「屬於路線」的分數，再由 decoder 負責有效性。

## 3. 模型的輸入與輸出

### 3.1 訓練時的輸入

對一個案例，模型使用三類資訊：

1. **城市座標 `P`**：形狀 `[B,N,2]`。`B` 是批次大小，`N` 是城市數。這裡的訓練迴圈一次處理一個案例，所以實際上常是 `[1,494,2]`。
2. **某個擴散時間的雜訊邊矩陣 `X_t`**：形狀 `[B,N,N]`，每格是 0 或 1。
3. **時間步 `t`**：告訴網路這張矩陣被破壞到什麼程度。

模型也從座標計算正規化後的城市間距離，作為邊特徵的一部分。座標會先以案例中心平移並按尺度正規化，避免模型只記住某一組絕對位置或座標範圍。

因此可以把模型條件寫成：

```text
神經網路輸入 = 城市位置 P + 雜訊邊 X_t + 時間 t
```

### 3.2 正向加噪如何做

乾淨標籤記為 `X_0`。每個訓練樣本隨機抽一個時間步 `t`，再依累積轉移機率 `Q̄_t = Q_1 Q_2 … Q_t`，把 `X_0` 中的邊逐格變成 `X_t`。每一小步的轉移大致是：

```text
Q_t = (1 - β_t) I + β_t / 2 · 1
```

其中 `β_t` 是該步的雜訊比例。此專案預設總步數 `T=32`，`β` 從 `0.0001` 線性增加到 `0.02`。直覺上，每次大多保留原本的 0 或 1，少部分機率改成隨機類別；走得越久，原本的路線資訊越不明顯。

訓練時**不是**每筆資料都完整跑完 32 次再訓練一次。每次更新會抽一個 `t`，直接抽樣得到該時間點的 `X_t`，讓網路學會處理不同噪聲程度。這樣能用一次模型前向運算訓練多種時間步。

### 3.3 網路內部大致做什麼

目前的 `DIFUSCOTSP` 是本專案的精簡圖神經網路實作：

1. 以小型 MLP 把每座城市的座標編成 node embedding。
2. 為每一對城市建立 edge embedding，輸入包含雜訊邊狀態與正規化距離。
3. 把時間步轉成 sinusoidal time embedding，讓網路知道現在噪聲程度。
4. 經過多層 gated edge message passing，讓節點資訊與邊資訊互相更新。
5. 對每個有序城市對輸出兩個類別的分數（logits）：不選這條邊、選這條邊。
6. 將矩陣和轉置矩陣的 logits 平均，維持預測對稱。

預設隱藏維度是 16、訊息傳遞層數是 2。這些是小型實驗設定，不代表 DIFUSCO 論文中唯一或標準的網路大小。

### 3.4 模型的輸出不是路徑

輸出 logits 的形狀是 `[B,2,N,N]`。對每個城市對，softmax 轉成兩類機率：

```text
p(edge=0 | P, X_t, t)   # 不在路線中的分數
p(edge=1 | P, X_t, t)   # 在路線中的分數
```

反向擴散的最後結果是一張 `[N,N]` 的浮點數熱度圖（edge heatmap）：每個值代表模型對該邊的偏好／機率分數。它**不是** `[城市順序]`，也不保證每個城市恰好有兩條邊、沒有子迴圈或形成單一巡迴。這就是為何後面仍需要 decoder。

要記得分清楚三個物件：

| 物件 | 值的型態 | 是否一定是合法巡迴 |
|---|---|---|
| 訓練標籤 `X_0` | 0/1 邊矩陣 | 是參考巡迴的邊表示 |
| 模型 logits／機率 | 每條邊的兩類分數 | 否 |
| decoder 路線 | 城市索引順序，例如 `[0, 5, 2, …, 0]` | 是，每城一次並回到起點 |

## 4. 訓練流程：從資料到 checkpoint

整個訓練程序可以用下面的流程理解：

```text
座標 + OR-Tools 參考路線
          │
          ├─ 將路線轉成對稱二元鄰接矩陣 X₀
          │
          ├─ 隨機抽時間步 t，對 X₀ 加噪得到 Xₜ
          │
          └─ (座標 P, 雜訊 Xₜ, 時間 t) ──> DIFUSCOTSP ──> 每條邊 0/1 logits
                                                           │
                                     與乾淨 X₀ 比較，算交叉熵 loss <─┘
                                                           │
                                             反向傳播更新模型權重
```

### 4.1 資料切分

程式以固定種子 `42` 打亂案例索引，再切成：

- 70% 訓練集
- 15% 驗證集
- 15% 測試集

1000 筆時就是 700 / 150 / 150。驗證集用來觀察訓練期間的 loss、選出驗證 loss 最低的 checkpoint；測試集應保留作最後評估。切分固定種子讓相同資料數量時可重現；如果資料總數改變，分割集合也可能跟著改變。

### 4.2 一筆訓練更新

每筆訓練案例大致執行以下步驟：

1. 取出座標 `P` 和乾淨鄰接矩陣 `X_0`。
2. 隨機抽時間步 `t`，依擴散轉移抽出雜訊矩陣 `X_t`。
3. 把 `P, X_t, t` 放入模型，得到每個城市對的兩類 logits。
4. 用 `X_0` 當正確答案計算交叉熵（Cross Entropy）；忽略矩陣對角線。
5. 對 loss 反向傳播，使用 AdamW 更新參數，並限制梯度範數以避免更新過大。

模型學的是「看到座標和一張被污染的邊圖後，原本每一格是 0 還是 1」。由於標籤是參考巡迴，loss 會鼓勵模型恢復 OR-Tools 找到的那些邊。loss 低代表逐邊分類更接近標籤，不等於最終路線必然更短；路線品質還會受反向採樣、decoder 和參考解品質影響。

因為標籤與 logits 都是對稱矩陣，實作會把兩個方向的格子都計入（對角線除外）。同一條無向邊因此在矩陣 loss 中有兩個對稱位置。

### 4.3 Epoch、驗證與最佳模型

一個 epoch 是將訓練索引走過一輪。每輪後在最多 32 筆驗證資料上計算驗證交叉熵。若驗證 loss 優於目前最佳值，就儲存該模型 checkpoint。訓練歷史會供 loss curve 使用。

預設主要參數：

| 設定 | 預設值 | 用途 |
|---|---:|---|
| Epochs | 20 | 訓練集重複幾輪 |
| 擴散訓練步數 `T` | 32 | 正向／反向擴散時間尺度 |
| Learning rate | `2e-4` | 權重更新步幅 |
| Weight decay | `1e-5` | AdamW 正則化 |
| Hidden dimension | 16 | 節點／邊隱藏特徵大小 |
| Message passing layers | 2 | 訊息傳遞層數 |
| Gradient clipping | 1.0 | 梯度範數上限 |
| 驗證筆數上限 | 32 | 每 epoch 驗證 loss 的案例數 |
| 推論步數 | 8 | 反向擴散採樣採用的步數 |

不同命令列選項可覆寫預設值；實際某次 run 的設定以該 run 的 `params.json` 為準。

### 4.4 訓練產物

每次訓練會在 `results/runs/<run_id>/` 建立結果，通常包含：

- `params.json`：本次訓練與評估參數。
- `difusco_tsp.pth`：模型權重 checkpoint。
- `loss_curve.png`：訓練／驗證 loss 隨 epoch 的變化。
- `gap_metrics.json`：路線品質統計。
- `mean_gap_histogram.png`：每筆案例 gap 分布及平均指標圖。
- best / average / worst comparison 圖：選定案例中模型路線與 OR-Tools 參考路線的比較。
- `report.json`：彙整評估數字與輸出位置。

`results/runs/latest.txt` 指向最近一次 run。Smoke test 為了快速確認流程，只用少數案例、少量 epoch 和較少推論步數；它能證明程式流程跑通，不能用來主張模型有穩定或良好的統計表現。

## 5. 推論：反向擴散如何產生邊熱度

訓練完成後，推論不再使用正確答案 `X_0`。程式從隨機二元邊狀態開始，在一系列時間步反覆執行：

1. 把目前狀態 `X_t`、座標與時間步送進網路。
2. 網路估計乾淨狀態 `X_0` 的每格類別機率。
3. 結合擴散轉移機率，抽樣出較早時間點的狀態 `X_{t-1}`。
4. 重複直到接近時間 0。
5. 整理為對稱的連線分數矩陣，對角線設為 0。

完整訓練擴散步數預設 32，但推論可用較少步數加速，預設為 8。少步數通常更快，但生成品質可能改變。由於反向過程含隨機抽樣，同一模型多次跑同一案例也可能得到不同熱度圖與路線。

## 6. Decoder：如何從分數圖變成一條巡迴

### 6.1 先把機率轉成成本

decoder 接收 `[N,N]` 的 edge heatmap。高分代表模型較偏好這條邊。程式將分數轉成成本：

```text
C(i,j) = -log(p(i,j) + 1e-9)
```

高機率的邊成本低，低機率的邊成本高。decoder 接下來嘗試在構造合法巡迴的同時，偏向使用成本低的邊。

### 6.2 Divide-and-conquer 分群

城市數多時，直接對 494 個城市做精確 TSP 搜尋不可行。decoder 依座標用 KMeans 遞迴切分城市，直到每個子群不超過 12 個城市。每群先各自形成局部巡迴，再逐群合併。

### 6.3 子群內 Held–Karp

每個最多 12 城市的小群使用 Held–Karp 動態規劃，找該群在模型邊成本下的低成本巡迴。這種方法在小問題上可做精確搜尋，但它只對**這個子群**精確；不代表整個 494 城市的全域 TSP 解是精確最優。

### 6.4 合併子群巡迴

合併時參考群中心距離，最多考慮 2 個候選未合併群（`CANDIDATE_LIMIT=2`），並使用寬度 2 的 beam search（`BEAM_WIDTH=2`）保留少數較好的合併狀態。對兩條巡迴，嘗試切開邊並以交叉連線方式接成一條更大的巡迴，選擇增量成本最低的選項。

此步驟是有限候選的近似搜尋；它不會窮舉所有可能的分群順序與合併方式。

### 6.5 2-opt 幾何改善

合併後再用最多 5 輪 2-opt 嘗試縮短路線。2-opt 會選兩條路線邊，反轉中間一段；若新的兩條連線使總歐氏距離變短，就接受交換。這個步驟使用城市座標的幾何距離，而非前面 `-log(p)` 的神經網路成本。

最後把路線旋轉到城市 0 開始，並在尾端再放一次起點，形成 `[0, …, 0]` 的閉合路線。decoder 建立合法巡迴，但它是本專案的自訂近似 decoder，仍不保證得到全域最短解。

## 7. 評估數字與圖表怎麼讀

評估會對同一案例分別計算模型路線與 OR-Tools 參考路線的幾何路長，單位都是 km：

```text
extra_km = model_length_km - ortools_length_km
gap_percent = extra_km / ortools_length_km × 100%
```

- `extra_km > 0`：模型路線比 OR-Tools 參考路線多走這麼多公里。
- `extra_km < 0`：模型路線比該次 OR-Tools 參考路線短。
- `gap_percent > 0`：模型相對參考路線較長。
- `gap_percent < 0`：模型相對參考路線較短。

負 gap 不代表模型證明了真正最優解，也可能只是模型在該案例找到一條比 OR-Tools 這次啟發式結果更短的巡迴。由於 OR-Tools 標籤不是已知全域最優值，這裡的 gap 是**相對於 OR-Tools 參考解的差距**，不是嚴格的 optimality gap。

輸出會統計平均 gap、95 百分位 gap、平均路長與平均多走公里數，也會產生：

- **Mean gap／extra km 圖**：看整體平均表現。平均值容易受少數很差的案例影響，因此最好和分布一起看。
- **Gap histogram**：看各案例 gap 集中在哪裡，以及有沒有長尾或離群案例。
- **Best / average / worst case 比較圖**：將模型與 OR-Tools 路線畫在同一組城市座標上，標出路長、gap 與多走公里數。這三張圖是挑選案例展示，不能取代全部測試案例的統計。

Tune 使用的目標是 `mean_gap + 0.1 × p95_gap`。這讓平均品質重要，同時對較差尾端案例加一點懲罰；它仍是相對 OR-Tools 的調參目標。

## 8. Optuna 調參在做什麼

`tune.py` 會建立多個 Optuna trial。每個 trial 抽一組訓練設定，啟動短訓練，再在驗證集上計算上述目標分數；分數較低的組合較好。預設搜尋範圍大致包含：

- learning rate：`5e-5` 至 `8e-4`（對數尺度）
- weight decay：`1e-6` 至 `1e-3`
- hidden dimension：8 或 16
- message passing layers：1 或 2
- 擴散步數：16 或 32
- 推論步數：4 或 8

預設 trial 數、訓練 epoch、案例數都偏小，目的在確認調參流程並探索方向，不足以得出穩健的最佳參數結論。找到的設定會存到 `results/optuna/best_params.json`；訓練可選擇套用它。嚴謹比較仍應固定資料切分、增加 trial 與訓練量，並用未參與調參的測試集評估。

## 11. 目前實作的界線與解讀結果時的提醒

1. **這是受 DIFUSCO 啟發的精簡實作。**專案使用自訂 gated edge message passing、自己的訓練／採樣程式和自訂 decoder；不能描述成直接使用官方 DIFUSCO 完整模型或官方 decoder。
2. **標籤是 OR-Tools 啟發式路線。**模型主要在模仿這些參考邊，資料標籤本身不保證最優。
3. **熱度圖不等於合法路線。**合法性來自 decoder 的構造程序，模型本身不強制每城度數為 2 或只形成一個迴圈。
4. **Loss 不等同路長。**交叉熵測每條邊的分類誤差，路線長度是經 decoder 後的全局結果；兩者相關但不是同一個目標。
5. **Smoke test 只驗證流程。**一筆或少數案例、單一 epoch 的指標很容易波動，不能作為正式效能結論。
6. **Dense 邊矩陣有平方級成本。**城市數是 `N` 時，模型需處理約 `N²` 對邊；城市數加倍，邊位置約變四倍。
7. **decoder 是近似法。**分群、有限 beam 合併和有限輪 2-opt 加快了大案例處理，但不保證全域最優。
8. **反向採樣有隨機性。**同一模型同一案例重跑，路線品質可能不同。比較方法時要盡量固定 seed，並多跑幾次、多看案例分布。
9. **目前小型資料量與模型規模限制泛化判斷。**若要報告可靠結論，應保留測試集、增加不同隨機種子實驗，報告多次平均與變異，並明確說明案例數、節點數及計算資源。

## 12. 報告時可以怎麼講

> 本專題將 TSP 巡迴表示成城市間的二元邊矩陣。訓練時，我們以 OR-Tools 產生參考巡迴，隨機抽取擴散時間並對邊矩陣加上類別式雜訊，再讓圖神經網路根據城市座標、雜訊矩陣與時間步預測原始邊標籤，並以交叉熵更新參數。推論時從隨機邊矩陣開始反覆去噪，得到每一對城市的連線分數。這個分數矩陣不是合法路徑，因此再交給 divide-and-conquer decoder：先分群、解小群、合併巡迴，最後用 2-opt 改善路長。評估時比較模型與 OR-Tools 參考路線的公里數及相對 gap。由於 OR-Tools 結果是啟發式參考值，這個 gap 不代表和真正最優解的差距。

### 常見提問

**Q：擴散模型最後輸出什麼？**  
A：反向擴散最後提供城市對的連線熱度／機率矩陣，不是城市順序。decoder 才輸出閉合巡迴路線。

**Q：為什麼模型輸出不能直接當路線？**  
A：逐格預測可能讓一個城市連到零條、一條或很多條邊，也可能形成多個小迴圈。合法 TSP 需要全部城市恰好形成一個巡迴，decoder 負責組合與修正。

**Q：為什麼選擴散模型？**  
A：它能從資料學習結構化輸出的分布，並透過多步反向去噪產生邊分數。這個專題用離散擴散處理二元邊狀態；但是否比其他方法好，仍須透過相同資料、計算預算和基準的實驗比較來回答。

**Q：平均 gap 是對真正最佳解嗎？**  
A：不是。現在的基準是 OR-Tools 啟發式參考巡迴，所以 gap 表示相對於該參考解的路長差。

**Q：loss 下降是否代表路線一定變短？**  
A：不一定。loss 衡量邊分類是否接近參考矩陣；最後路長還要經過隨機反向採樣和 decoder。應同時看 loss、平均 gap、extra km、分布和案例圖。

## 13. 名詞小抄

| 名詞 | 白話解釋 |
|---|---|
| Node / 節點 | 一座城市 |
| Edge / 邊 | 兩座城市之間的連線 |
| Adjacency matrix / 鄰接矩陣 | 用矩陣記錄每對城市是否相連 |
| `X_0` | 乾淨的參考邊矩陣 |
| `X_t` | 擴散到時間 `t` 後的雜訊邊矩陣 |
| Logits | softmax 前的模型原始分類分數 |
| Edge heatmap | 每條候選邊的預測分數矩陣 |
| Decoder | 把邊分數變成合法城市巡迴的演算法 |
| Epoch | 訓練資料完整走過一輪 |
| Loss | 訓練時衡量預測與標籤差距的數值 |
| Checkpoint | 儲存下來、可供之後推論的模型權重 |
| 2-opt | 交換兩條邊、反轉路線一段以嘗試縮短距離的局部搜尋 |
| Mean gap | 相對參考路線的平均百分比長度差 |
| Extra km | 相對參考路線平均多走／少走的公里數 |
